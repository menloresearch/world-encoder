## Risks (silent breakage)

1. **Venv cross-contamination**: running regen/eval in the robocasa venv "works" until env construction
   garbles the controller (`robot_env.py:213` treats OSC_POSE dict as composite config → empty
   `body_parts`); mimicgen in robocasa venv breaks robocasa import.
2. **reset_to F/T fidelity**: sensor values come from `sim.forward()` at a restored state (no solver
   warm-start/actuation history) — may differ from live-stepped readings; step 11 gates this.
3. **Normalizer/obs-space suffix whitelists** (3 sites: replay dataset :179, hdf5 dataset :243, wrapper
   obs space) — miss one and it crashes at first train/eval step, or worse, a `*pos`-suffixed rename
   silently range-normalizes garbage.
4. **Stale zarr cache**: cache key is `dataset_path + '.zarr.zip'` (`robomimic_replay_image_dataset.py:54`)
   — after any regen, use a new filename or delete the cache, else training silently uses old obs.
5. **Window padding mismatch** between `add_ft_window.py` and the eval wrapper deque → train/eval
   distribution shift with no error.
6. **`shape[0]` flattening**: declaring ft_window as `[40,6]` makes DensePatch size `low_proj` for 40
   dims, not 240 — declare flat.
7. **Observable lifecycle**: any code path that registers via `env.add_observable` instead of the
   `_setup_observables` patch loses the key after the first hard reset — obs dict then KeyErrors (regen)
   or the wrapper crashes (eval).
8. **Disk**: local `/` has 18G free (97%); downloads + regen + zarr caches all to `/mnt/nas` (6.2T free).
9. **coffee_d0 states assumption**: verified only by file size; if `states` absent, F/T cannot be added
   to Coffee → fallback is mimicgen source-dataset regeneration (much larger scope).
10. **Headless rendering** in the new venv (mujoco 2.3.x + EGL) — verify one frame renders before
    launching full regen.
