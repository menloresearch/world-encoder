## 1. Why state-as-query (evidence already verified, REDESIGN_RESEARCH_20260729.md)

- AdapTac (strongest force-fusion result in corpus): privileged modality forms the cross-attn
  **queries** over other sensors' K/V — 93% vs 73% vision-only. BUT its own ablation shows the
  wiring alone loses to vision-only; the **future-prediction aux is the driver**. Query design
  and objective are ONE package.
- MCR (only frozen-encoder pretrain with real policy wins) is built on state-action grounding —
  its dynamics-alignment term is the largest ablation factor.
- Manipulation-centricity (attention on EE + task objects) predicts policy success (R≈0.93);
  state-conditioned queries are a mechanism that aims attention exactly there.
- Known failure mode: **proprio shortcut** (DiT-Block Policy needed per-dim state dropout) — on
  the encoder side this means queries extracting only state-predictable content. Mitigation +
  detection is a first-class design axis, not an afterthought.

## 3. Fast-iteration protocol (screen cheap, confirm once)

Funnel — each stage kills before the next spends:

1. **Free offline pre-filter (~minutes, no policy run):** action-readout ladder (clean episode
   split), state R², RankMe, SeeSE3 dSE3@0.25s, + (pending agent-04 recipes) Burns CLS-attention
   Jaccard and MCR manipulation-centricity on the encoder ckpt. Probes are NECESSARY-not-
   sufficient here (v0.3 lesson: they invert as sufficiency signals) — used only as sanity
   floors + shortcut detectors (state-zeroing sensitivity).
2. **Encoder pretrain:** ~2-4h on the robocasa cache (E3 harness), co-residable 2-3/GPU.
3. **Policy screen (1 seed):** standard recipe, `checkpoint_every=10`; **gate at ep10-20** once
   the calibration data (ep10/20/30/40/50 curves now accumulating from un-pool + insertion arms)
   shows early rank predicts ep50 rank. Kill discipline per [[early-kill-discipline]]: gates
   pre-registered BEFORE numbers are seen.
4. **Fast eval for screens:** reduced-step diffusion inference (DDPM-16 / DDIM-16, validation
   run vs the known 66% square ckpt IN FLIGHT) + 50 rollouts. 25-rollout screens only for
   ≪-band kills (binomial noise at p≈0.5: ±2σ ≈ ±14pp @25, ±10pp @50 — 25 can kill, not rank).
5. **Confirm (top-2 only):** ep50+ep100, DDPM-100, 50 rollouts, 1 seed.
6. **THE BIG RUN (winner only):** 2-3 seeds, ep100+, standard eval, + transfer tasks
   (tool_hang/coffee if force is in the design). Nothing else ever gets multi-seed compute.

Throughput math: screen ≈ 2-4.5h train (ep10-20) + ~15-25min eval; 20GB arms co-reside 2/GPU on
the A6000s → ~10-14 concurrent screens box-wide when v0.3 runs clear ⇒ ~8-12 verdicts/day vs
current ~2-4. Encoder-side diagnostics (gate value off zero, state-zeroing delta) read straight
from ckpts at ep10 — a dead arm dies without a single rollout.

## 7. JQ encoder-rebuild sketch (Slack 07-31 1:10am) — assessment

**The sketch:** per-modality Conv1d-over-T stem (P→d), spatial compress S→n_s (perceiver |
avgpool), temporal resample T→R, then fusion = flatten [B,R,3·n_s·d] → Linear → d → self-attn
over R → pool → [B,d]. Hide-one = zero the modality slice pre-linear; T=1 through the resampler
(one code path); mm_perceiver3 objective unchanged; ee_mask handled in the temporal resampler;
new training script, strict [B,T,S,P]. Follow-up question (Ishneet): big-width fusion
transformer + MLA to handle the flattened dimension?

**MLA verdict: not applicable.** MLA is KV-cache compression for autoregressive decode; the
fusion attention here is one bidirectional pass over R≈8-32 tokens — no cache, nothing to
compress, and training-FLOPs MLA ≈ MHA plus extra projections. The real cost of a wide trunk
is the FFN (~2/3 of ~12·D²/layer; D = 3·n_s·d = 6144 at n_s=8, d=256 → ~450M params/LAYER vs
the whole current encoder at a few M), which MLA doesn't touch. A trunk that size also breaks
the §3 screening economics (2-4h encoder pretrains) and is an overfit risk at our data scale.

**The legit worry underneath:** flatten→Linear is a 24× per-timestep bottleneck (6144→256)
applied BEFORE any temporal attention, and it is the ONLY cross-modal contact point in the
sketch (stems + spatial compress are per-modality) — a late-fusion move against the 07-21
composition evidence (early > single > late).

**Counter-proposal (keeps everything else in the sketch):** don't flatten — after the resample
keep [R, 3·n_s] tokens at width d with modality+slot embeddings, self-attn over R·3n_s ≈ 384
tokens (cheap; fusion becomes multi-round attention instead of one linear), learned-query pool
→ [B,d]. Hide-one = attention-mask the modality's tokens (the existing True=BLOCKED machinery;
zero-slice leaks a learnable "hidden" symbol through the linear's bias); ee_mask rides the same
mask path. Worth adopting from the sketch regardless: strict [B,T,S,P] + one code path incl.
T=1, the T→R resampler (current temporal context grows linearly in T: C·217 tokens), Conv1d
stem as a screenable arm. If fusion capacity is ever the binding constraint: depth at d=256 or
factorized within-tick/across-R attention before width; GQA + narrow FFN over MLA if width.

### §7.1 Thread outcome (JQ replies, Slack 08-01 ~7:20am) — R-length, layered cross-attn, dual-path

JQ's three follow-ups: (1) MLA "depends on how long R is gonna be"; (2) re-inject the original
information over multiple layers via cross-attn — self-withdrawn in-thread ("maybe not nvm");
(3) dual-path spatial and temporal — assessment requested.

**R-length gates the joint-vs-factorized choice, never the MLA one.** MLA's payoff is KV-cache
memory during autoregressive decode; a bidirectional single-pass encoder has no cache at ANY R.
What R does gate: under the no-flatten counter-proposal the trunk sees N = R·3n_s tokens
(R=16 → 384, trivial; flash attention keeps joint attn feasible well into the thousands).
Past R ≈ 50-100 unflattened, factorized within-tick/across-R becomes the efficiency move —
already §7's named escalation. And R shouldn't get there: it's the resampler's OUTPUT rate,
ours to choose (8-32 in every sketched use); absorbing long inputs (100Hz force windows) is
the resampler's job, not the trunk's.

**Layered cross-attn re-injection: agree with the withdrawal, for a keepable reason.** It's the
Perceiver-IO/Flamingo pattern — the correct escalation IF the single cross-modal contact point
proves lossy. The no-flatten variant keeps per-slot tokens in the stream and buys most of the
same thing with zero new machinery. Shelve, don't kill.

**Dual-path: two readings, one verdict — not first.** (a) Alternating within-tick / across-R
layers (DPRNN/SepFormer-style ≈ TimeSformer divided attention): the right escape hatch when N
binds, but at N≈384 joint attention is affordable and strictly more expressive — factorizing
removes cross-(tick,slot) interactions we can afford to keep. (b) Two parallel branches
(spatial-first ∥ temporal-first) merged at the end: structurally the late-fusion shape the
07-21 composition analysis penalized (early > single > late; per-view-encode+avg lost to the
best single view) — separately pooled summaries can't cross-talk during extraction. Steelman
for (b): per-tick spatial compress is motion-blind; a temporal-first path keeps per-location
dynamics. But the sketch's own Conv1d-over-T stem already gives every token LOCAL temporal
context before spatial compress, and the residual risk (long-range per-location dynamics dying
in the per-tick compress) is a 2-4h probe on the first build, not a second path: future-force /
dSE3@0.25s readout from R-tick z vs per-frame carry. Build single-path joint first;
pre-register dual-path as the arm added only if that probe fails.
